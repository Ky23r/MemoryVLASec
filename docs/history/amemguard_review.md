# A-MemGuard implementation review

**Scope.** Reviewed against the [A-MemGuard paper](https://arxiv.org/html/2510.02373v1) (Sections 4, Appendices A and G) and [official repository](https://github.com/TangciuYueng/AMemGuard), particularly `ReAct/consistency.py`, `ReAct/local_wikienv.py`, and `EhrAgent/ehragent/medagent.py`. This project implements a MemoryVLA-specific inference adapter, not a reproduction of the paper's LLM-agent method.

## Current workflow

1. The defended BadVLA/DropVLA scripts obtain an attack checkpoint, calibrate a cosine radius from clean LIBERO transitions if needed, and run defended LIBERO evaluation. The JSON artifact contains parameters and provenance, not learned detector weights ([scripts/_common.sh](https://github.com/Ky23r/MemoryVLASec/blob/ffe5734e/scripts/_common.sh), [scripts/calibrate_amemguard.py](https://github.com/Ky23r/MemoryVLASec/blob/ffe5734e/attacks/dropvla/scripts/calibrate_amemguard.py), [main.py](https://github.com/Ky23r/MemoryVLASec/blob/ffe5734e/main.py)).
2. `SecureVLA` attaches filters and plan guards to the cognition and perception memory banks ([models/secure_vla.py](https://github.com/Ky23r/MemoryVLASec/blob/ffe5734e/models/secure_vla.py)). For each stored episode-history item, the bank runs its normal retrieval and fusion with that item alone, then subtracts memory-free fusion to obtain a current-state-conditioned influence tensor ([models/core/vla/memory_vla.py](https://github.com/Ky23r/MemoryVLASec/blob/ffe5734e/models/core/vla/memory_vla.py)).
3. `AMemGuard` mean-pools and normalizes those tensors, applies cosine-distance density clustering, and admits only the largest cluster before ordinary multi-entry attention. Rejected paths become bounded, in-process lessons paired with pooled current-state context. With too few candidates it admits all; with no cluster it admits none and creates no lessons ([defenses/amemguard.py](https://github.com/Ky23r/MemoryVLASec/blob/ffe5734e/defenses/amemguard.py)).
4. Before diffusion action sampling, each bank compares its proposed fused conditioning against lessons using context and influence similarity. A match replaces that bank's conditioning with memory-free fusion. LIBERO results record rejection, lesson, hit, and revision counts ([models/core/vla/memory_vla.py](https://github.com/Ky23r/MemoryVLASec/blob/ffe5734e/models/core/vla/memory_vla.py), [utils/libero_evaluate.py](https://github.com/Ky23r/MemoryVLASec/blob/ffe5734e/utils/libero_evaluate.py)).

## Fidelity and gaps

- **Matches the framework's structure:** query-conditioned per-memory validation, exclusion before final memory use, a separate negative-lesson store, and a pre-action revision step correspond to the paper's two mechanisms. Largest-cluster cosine DBSCAN also matches the [repository's clustering option](https://github.com/TangciuYueng/AMemGuard/blob/main/ReAct/consistency.py), although the paper treats it as an alternative to its main LLM judge.
- **MemoryVLA adaptation:** latent retrieval/fusion influence replaces textual entity-relation reasoning chains; each bank's full bounded episode history replaces retrieval of top task-relevant text records. Mean pooling discards token-level differences. The fallback changes conditioning for continuous action generation rather than supplying an explicit warning and asking an LLM to revise a semantic plan.
- **Material omissions:** there is no LLM consistency/safety judgment, semantic lesson, action-similarity search over stored examples, or explicit corrective instruction. Lessons live only for the process and are capped at 256 per bank; they are not included in the calibration artifact. Filtered entries are excluded from the current retrieval but are not purged from the underlying bank ([defenses/amemguard.py](https://github.com/Ky23r/MemoryVLASec/blob/ffe5734e/defenses/amemguard.py), [models/core/vla/memory_vla.py](https://github.com/Ky23r/MemoryVLASec/blob/ffe5734e/models/core/vla/memory_vla.py)). These choices limit transfer from the paper's claimed security results.
- **Operational limits:** a coherent poisoned majority can become the accepted cluster; one-item histories receive no validation. Clean-distance quantile calibration is a heuristic and does not establish a secure threshold. The repository's ReAct path itself implements filtering without the full lesson loop; its EHRAgent path annotates rejected examples and injects retrieved lessons into later prompts ([ReAct integration](https://github.com/TangciuYueng/AMemGuard/blob/main/ReAct/local_wikienv.py), [EHRAgent integration](https://github.com/TangciuYueng/AMemGuard/blob/main/EhrAgent/ehragent/medagent.py)).

**Assessment.** The filter → lesson → pre-action fallback loop is wired end to end and logically complete as a *latent MemoryVLA analogue*. It is only structurally faithful to A-MemGuard: the paper's main semantic validation and deliberative correction are absent. The four focused unit tests pass, but this review found no evidence here that the adapter reproduces the paper's attack-success or benign-utility results on LIBERO ([tests/test_amemguard.py](https://github.com/Ky23r/MemoryVLASec/blob/ffe5734e/attacks/dropvla/tests/test_amemguard.py)).
